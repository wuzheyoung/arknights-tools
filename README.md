# 明日方舟 · 集成战略「黑流树海」战术终端

一套面向《明日方舟》集成战略玩法「黑流树海」的全自动战术辅助工具：对游戏截图进行高精度 OCR 识别、与本地骨架蓝图（`Layer_Skeletons.json`）对齐还原地图拓扑，并通过 A* 推演引擎给出收益最大化的行动路线。

> GUI 标题：`黑流树海 - 全自动战术终端 V7.7 (全兼容排版版)`

---

### 使用流程

1. **加载游戏截图**
   - 在游戏中打开本层拓扑界面后截图（或复制到剪贴板）。
   - 点击「📋 从剪贴板提取」或「📂 从本地文件选择」加载图片。
2. **提取拓扑特征**（🔍 提取图像拓扑特征存入系统）
   - 程序在后台线程初始化 EasyOCR 引擎，识别节点文字，与骨架蓝图对齐。
   - 起点留空时，自动采用骨架固定起点；日志区会输出 ASCII 可视化地图拓扑。
3. **配置参数**
   - 当前层数 / 当前 AP / 起点坐标（留空自动取骨架起点）。
   - 预设骨架（选填）：可输入 `template_id`（如 `Layer_1-3`）限定匹配范围。
   - 持有加工品数量：报废轮子、报废假肢、标准引擎、重弹簧、气垫底座、试作外骨骼、一次性喷气背包、老妈妈的融雪、坎诺特的触须、结构性原理、简易遥控器。
   - 战术偏好：⚔️ 倾向战斗 / 🛡️ 避免战斗（互斥）/ 🌟 探索未知。
   - 必经节点坐标：多个用 `|` 分隔（如 `1,2|3,4`）。
4. **生成路线**（⚡ 生成最佳战术路线 ⚡）
   - A* 推演引擎计算最优路线，输出**收益得分**、**最终余留 AP** 及逐步行动日志。

## 核心模块

### 模块一：战术推演核心算法（A* 寻路引擎）

- 入口：`solve_tree_sea_path(data, prefer_combat, avoid_combat, explore_map, layer=None)`
- 返回：`(路线步骤列表, 最高收益分, 剩余 AP, 错误信息)`
- **节点价值评估**：战斗 +1.0 / 紧急作战 +1.5 / 不期而遇 +1.3 / 狭路相逢 +1.5、未知诡秘/羽瞰探索 +1.2、羽瞰 +1.5、险路小径视剩余 AP 给 +2.5/+0.3、误入奇境视零件给 +4.0/+0.1、秘境行商在 AP≤2 时联动 ±8.0 等；支持「倾向战斗 +0.8」加成。
- **出口识别**：`type=='exit'` 或名称属于 `{险路恶敌, 险路小径, 险路尽头}` 或骨架 `fixed_type=='exit'`。
- **结算规则**：第 5、6 层允许在任意节点结束；其他层有出口时必须走到出口结算。
- **未知节点预测**：对「未知的诡秘 / 未知的凶戾」按本层已见子类型做排除法概率预测（含"紧急作战每层至少一个"等规则）。
- **剪枝优化**：
  - Pareto 支配剪枝（同状态更高分/更多 AP 则淘汰劣支）；
  - 乐观上界剪枝（剩余未访问节点即使全拿最高分也追不上已知最优解时提前放弃）；
  - 状态去重 + 迭代上限 500,000，保证大图快速收敛。
- **加工品系统**：部分零件消耗 AP 换取收益，简易遥控器 +3 AP，坎诺特的触须可将路线导向商店等。

### 模块二：高精度 OCR 与拓扑匹配（`DynamicTopologyRecognizer`）

1. **图像预处理**：2x 放大（INTER_CUBIC）+ 灰度化 + CLAHE 对比度增强。
2. **OCR 识别**：EasyOCR `ch_sim` GPU，`allowlist` 限定 31 个有效字符，逐节点映射标准名/类型/是否有效。
3. **稀疏网格还原**：对识别到的节点像素坐标按 X/Y 方向聚类，换算为物理网格坐标。
4. **骨架对齐**：遍历该层所有骨架模板，对每个偏移量计算匹配分；**出口节点加权（±5）**，取最优模板；
   **最终拓扑严格采用骨架节点，不增删节点**，连线完全沿用骨架设定。
5. **节点信息优先级**（本轮强化）：
   ```
   fixed_name（骨架显式命名，如起点"起点"） > fixed_type（骨架锁定类型，如出口/战斗） > OCR 赋名
   ```
   - 起点节点由骨架 `fixed_name="起点"` 权威命名，无视 OCR 结果；
   - 出口/战斗节点类型由骨架锁定，名称优先取 OCR（区分险路恶敌/小径/尽头），
     OCR 缺失或空名时回退骨架默认名（出口→"险路尽头"，战斗→"作战"）；
   - 其余节点由 OCR 赋名，OCR 未识别到则兜底为「林间空地」。
6. **输出**：ASCII 可视化地图（含 `—— │ \ / X` 连线绘制）+ 结构化 `map_topology` / `player_state` 数据。

### 模块三：统一 GUI（`UltimateTerminalApp`）

- 加载截图（剪贴板 / 本地文件）→ OCR 识别 → 参数配置 → A* 推演，全程后台线程运行，日志实时刷新。
- 状态联动：起点留空自动取骨架固定起点；倾向战斗/避免战斗互斥开关。

## 骨架数据说明

- `Layer_Skeletons.json`：按 `template_id`（`Layer_{层数}-{序号}`）组织，每个模板包含
  `nodes`（`grid_x/grid_y`、可选 `fixed_name`、`fixed_type`）与 `edges` 连线。
- 当前数据：**43 个模板**；`fixed_name` 全部为「起点」（每模板 1 个，`fixed_type='start'`）；
  `fixed_type='exit'` 出口节点 75 个、`fixed_type='combat'` 战斗节点 29 个。
- 骨架信息优先级已在 `process_to_dict` 中落实：**骨架 `fixed_name` 最高优先**（起点），
  出口若骨架补充 `fixed_name` 亦会优先采用，否则维持 OCR 赋名。

### 重新生成骨架

```bash
python "D:/PyFile/common/arknights/rouge/build_skeletons.py"
```

- 从 `map.txt`（SVG 拓扑预览）解析节点与连线，坐标换算：`grid_y = MAX_Y - cy`（SVG y 轴向下）。
- 自动检测 `MAX_Y`；按 `template_id` 合并写入（同 id 更新，其它层保留）。
- 出口 SVG 类型（`danger-end / danger-enemy / exit`）统一记为 `fixed_type='exit'`，名称留给 OCR 细分。
- 生成新层骨架时，需在脚本中把 `LAYER` 修改为目标层数后重新运行。

## 常见问题（FAQ）

| 现象 | 处理 |
|---|---|
| 日志提示「OCR 引擎加载完毕，系统就绪！」迟迟不出现 | 首次运行需初始化 EasyOCR 模型；确认 `rouge/easyocr_models/` 下模型文件存在（离线加载）或联网下载 |
| 提示「无法与任何本地蓝图骨架对齐」 | 截图需包含完整本层拓扑且文字清晰；检查「当前层数」输入是否正确（骨架按 `Layer_{n}-` 前缀过滤） |
| 出口名称显示不对 | 出口类型由骨架锁定（`fixed_type='exit'`），细分名称依赖 OCR；OCR 识别失败时自动回退「险路尽头」 |
| 提示「指定的起点坐标不在当前地图数据中」 | 起点留空可自动采用骨架固定起点；手动输入请使用骨架坐标（格式 `x,y`） |
| 运算卡住 / 结果为空 | 检查必经节点坐标是否在地图内；AP 不足或必经条件无法满足时会提示「绝境警告」 |
